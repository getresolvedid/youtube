# 30-Second YouTube Shorts Production Standard
## Neural Networks — From Zero to Understanding AI

**Version:** 1.0  
**Target duration:** 30 seconds  
**Format:** 9:16 vertical  
**Narration:** Voice-over only  
**Music:** None  
**Visual style:** Clear educational animation with diagrams, visual metaphors, controlled camera movement, and readable on-screen text.

---

# 1. Purpose

Every Short in the Neural Network Series should be designed as a complete **30-second educational experience**.

The Short must:

1. Capture attention immediately.
2. Introduce one clearly defined question or problem.
3. Explain one core concept.
4. Use animation to make the explanation visible.
5. End with a memorable takeaway.
6. Connect naturally to the next episode when appropriate.
7. Keep all critical visual information inside the established YouTube Shorts safe zone.

The goal is not to compress a long lecture into 30 seconds.

The goal is to choose **one idea that can be understood in 30 seconds**.

---

# 2. Core 30-Second Structure

Use the following default structure:

| Time | Section | Purpose |
|---|---|---|
| 0:00–0:03 | Hook | Stop the scroll and create curiosity |
| 0:03–0:07 | Setup | Establish the question/problem |
| 0:07–0:17 | Core Explanation | Explain the main mechanism |
| 0:17–0:24 | Visual Example / Reveal | Make the concept concrete |
| 0:24–0:28 | Takeaway | State the idea clearly |
| 0:28–0:30 | Continuation | Optional next-episode hook |

This is the default structure, not a rigid requirement.

Timing may be adjusted when the concept benefits from a different rhythm.

---

# 3. 30-Second Timing Rules

## 0:00–0:03 — Hook

The first three seconds are critical.

The hook should:

- Ask a compelling question.
- Present a surprising fact or situation.
- Show an intriguing visual.
- Introduce a problem.
- Create a knowledge gap.

Avoid:

- Long introductions.
- Channel greetings.
- Logo animations that consume valuable time.
- Definitions before establishing curiosity.
- “In today's video...” openings.

### Example

**VO:**

> “How does AI actually learn?”

**Animation:**

- Begin with a clean frame.
- Neural-network nodes appear rapidly.
- One connection lights up.
- Camera begins a subtle push toward the network.

**On-screen text:**

> HOW DOES AI LEARN?

The title must remain inside the safe zone.

---

# 4. 0:03–0:07 — Setup

The setup explains why the question matters.

The viewer should understand:

> “Here is the problem we are about to solve.”

### Example

**VO:**

> “It doesn't start by knowing the answer.”

**Animation:**

- Present an input example.
- Send the information into a simple neural network.
- Network produces an incorrect prediction.
- Clearly visualize the mismatch.

**On-screen text:**

> PREDICTION

Do not introduce unnecessary terminology yet.

---

# 5. 0:07–0:17 — Core Explanation

This is the most information-dense section.

Only explain the central mechanism.

For a neural-network learning example:

**VO:**

> “It makes a prediction, checks how wrong it was, and adjusts itself.”

Break the sentence into visual beats:

### Beat 1 — Prediction

Show information moving through the network.

### Beat 2 — Error

Show the predicted answer compared with the expected answer.

### Beat 3 — Adjustment

Show network weights changing subtly.

### Beat 4 — Repeat

Show the process beginning again.

The animation should make the spoken explanation visible.

---

# 6. 0:17–0:24 — Visual Example / Reveal

Turn the abstract explanation into something intuitive.

Example:

```text
PREDICT
   ↓
CHECK ERROR
   ↓
ADJUST
   ↓
TRY AGAIN
```

The loop should repeat visually.

Each repetition can become slightly more accurate.

This creates a visual representation of learning.

### VO

> “Repeat that process again and again, and the network gradually learns patterns.”

The viewer should be able to understand the concept even if they do not remember the technical terminology.

---

# 7. 0:24–0:28 — Takeaway

The takeaway should compress the entire Short into one memorable statement.

### Example

**VO:**

> “That's the basic idea behind neural network learning.”

**On-screen text:**

> GUESS → ERROR → ADJUST → LEARN

The visual should become simpler rather than introducing new information.

---

# 8. 0:28–0:30 — Continuation

Use this section when the series benefits from a next-episode connection.

Examples:

**VO:**

> “Next: what is the neuron actually doing?”

or

**On-screen text:**

> NEXT: THE ARTIFICIAL NEURON

Keep this brief.

Do not sacrifice the main explanation just to add a CTA.

---

# 9. Voice-Over Standard

Every scene must contain both:

### VO Script

The exact words spoken.

### VO Direction

Instructions for how those words should be delivered.

VO direction should specify:

- Tone
- Pace
- Emphasis
- Pauses
- Energy
- Emotional intent
- Pronunciation of technical terms
- Relationship to animation timing

---

# 10. Voice-Over Style

The default voice should be:

- Clear
- Confident
- Curious
- Conversational
- Intelligent
- Beginner-friendly
- Not childish
- Not overly dramatic

The narrator should sound like someone explaining a fascinating idea to a smart friend.

Avoid:

- Artificial excitement
- Excessive shouting
- Overly theatrical delivery
- Monotone reading
- Excessive technical jargon
- Unnecessary filler words

---

# 11. VO Timing

The script must be written to fit approximately 30 seconds.

Do not write a script first and then force the animation to fit it.

Instead:

1. Decide the learning objective.
2. Divide the idea into visual beats.
3. Write concise VO.
4. Estimate speaking duration.
5. Adjust wording.
6. Synchronize animation with the final VO.

Every important visual event should have a reason to exist.

---

# 12. Voice-Over and Animation Synchronization

The animation should respond directly to the narration.

Example:

**VO:**

> “It makes a prediction...”

**Animation:**

A data signal travels through the network.

**VO:**

> “...checks how wrong it was...”

**Animation:**

Prediction and expected answer appear side by side.

**VO:**

> “...and adjusts itself.”

**Animation:**

Weights visibly change.

This creates a cause-and-effect relationship between narration and visuals.

---

# 13. Scene Animation Direction

Each scene should describe:

### Starting State

What is visible when the scene begins?

### Main Action

What changes?

### Timing

When does each action occur?

### Object Behavior

How do nodes, arrows, text, characters, or diagrams move?

### Camera

Should the camera:

- Hold
- Push in
- Pull out
- Pan
- Track
- Reframe

### Ending State

What should remain visible when the scene ends?

### Transition

How does the next scene begin?

---

# 14. Animation Principles

## One Main Motion at a Time

Avoid making every object move simultaneously.

The viewer should know what to look at.

## Animate Explanatory Relationships

If the narration says:

> “Information moves through the network.”

Animate information moving through the network.

If the narration says:

> “The network changes its weights.”

Animate the relevant weights changing.

## Avoid Decorative Motion Without Purpose

Particles, camera movement, and effects should support attention and comprehension.

Do not animate simply because the screen feels empty.

---

# 15. Camera Direction

Camera movement should support the explanation.

### Use a Push-In When:

- Introducing a specific neuron.
- Focusing on a calculation.
- Revealing a detail.

### Use a Pull-Out When:

- Showing the larger network.
- Connecting a detail to the whole system.
- Ending a concept.

### Use a Pan When:

- Following information moving through a wider diagram.
- Comparing two concepts.

### Hold the Camera When:

- The viewer needs to read text.
- A mathematical formula is being explained.
- The concept is already visually complex.

Avoid unnecessary camera movement during high-information moments.

---

# 16. On-Screen Text

On-screen text should reinforce the VO, not duplicate every spoken word.

Good:

**VO:**

> “It checks how wrong it was.”

**Text:**

> ERROR

Bad:

**VO:**

> “It checks how wrong it was.”

**Text:**

> It checks how wrong it was.

Use short visual anchors:

- PREDICT
- ERROR
- ADJUST
- LEARN

---

# 17. Text Timing

Text should:

1. Appear slightly before or exactly when it becomes relevant.
2. Remain visible long enough to read.
3. Disappear when it is no longer relevant.
4. Never compete with another important text element.

Do not display too many concepts simultaneously.

---

# 18. Neural Network Diagram Standard

For this series, neural-network diagrams should use consistent visual logic.

### Basic representation

```text
INPUT
  ○
  ○ ───── ○
  ○ ───── ○ ───── ○ OUTPUT
  ○ ───── ○
```

The exact visual style may evolve, but the meaning should remain consistent.

### Node

Represents an artificial neuron.

### Connection

Represents information flowing between neurons.

### Weight

Can be visualized through:

- Connection emphasis
- Numeric label
- Thickness
- Brightness
- Other consistent visual encoding

### Signal

Can be represented by:

- Moving dot
- Pulse
- Highlight traveling along a connection

---

# 19. Mathematical Concepts

When mathematics appears:

- Introduce one equation at a time.
- Keep equations large enough to read.
- Highlight the current variable.
- Visually connect the equation to the neural-network component it describes.
- Avoid showing complex formulas without explaining what they mean.

The animation should answer:

> “Why am I seeing this equation?”

---

# 20. Safe-Zone Integration

Every scene must follow the **YouTube Shorts Visual Safe-Zone Standard**.

Critical content includes:

- Titles
- Subtitles
- Labels
- Equations
- Important nodes
- Important arrows
- Character faces
- Main objects
- Calls to action

Keep these inside the central safe area.

Reserve the right side and lower area for potential platform UI.

The safe-zone check is mandatory before finalizing the scene.

---

# 21. Scene-Level Safe-Zone Check

For every scene:

- [ ] Critical text is inside the safe area.
- [ ] Important diagram components are inside the safe area.
- [ ] Important faces/objects are unobstructed.
- [ ] No essential label is near the right edge.
- [ ] No essential information is near the bottom edge.
- [ ] Camera movement does not move critical content into an exclusion zone.
- [ ] Animated objects remain safe during their final position.
- [ ] Subtitles remain safely positioned.
- [ ] The scene remains understandable with platform UI visible.

# 23. Example: Episode 1

## Title

**How Does AI Actually Learn? 🤖**

## Learning Objective

The viewer should understand the basic learning loop:

**Prediction → Error → Adjustment → Repeat**

The viewer does not need to understand backpropagation or gradient descent yet.

Those concepts belong to later episodes.

---

## Scene 01 — Hook

**Time:** 0:00–0:03

**VO:**

> “How does AI actually learn?”

**VO Direction:**

Curious and direct. Slight emphasis on **“actually learn.”** Ask the question as if the answer is surprising. Brief pause after “AI.”

**Animation:**

Start with a clean vertical frame.

A few neural-network nodes appear one after another.

Connections rapidly form between them.

One signal pulse travels through the network.

**Camera:**

Very subtle push toward the network.

**On-Screen Text:**

> HOW DOES AI LEARN?

**Safe Zone:**

Place title in the central upper/middle region, away from the right and bottom UI areas.

---

## Scene 02 — Setup

**Time:** 0:03–0:07

**VO:**

> “It doesn't start by knowing the answer.”

**VO Direction:**

Calm, explanatory. Emphasize **“doesn't start.”**

**Animation:**

A simple input enters the network.

The network produces an incorrect output.

Show:

> INPUT → NETWORK → WRONG ANSWER

Do not introduce technical terms such as weights or backpropagation yet.

**Camera:**

Hold mostly steady so the viewer can understand the sequence.

**On-Screen Text:**

> WRONG PREDICTION

---

## Scene 03 — Core Explanation

**Time:** 0:07–0:17

**VO:**

> “It makes a prediction, checks how wrong it was, and adjusts itself.”

**VO Direction:**

Use three distinct vocal beats:

**“makes a prediction”**  
**“checks how wrong it was”**  
**“adjusts itself.”**

Slight pauses between each beat.

**Animation:**

### Beat 1

Signal moves through the network.

Text:

> PREDICT

### Beat 2

Output appears next to the expected answer.

Text:

> ERROR

Visually show the difference.

### Beat 3

A few network connections subtly change.

Text:

> ADJUST

### Beat 4

Signal begins another pass.

---

## Scene 04 — Reveal

**Time:** 0:17–0:24

**VO:**

> “Repeat that process again and again, and the network gradually learns patterns.”

**VO Direction:**

Slightly increase energy during **“again and again.”**

Slow down slightly on **“gradually learns patterns.”**

**Animation:**

Repeat:

```text
PREDICT
   ↓
ERROR
   ↓
ADJUST
```

The prediction becomes progressively more accurate.

The final pass produces the correct result.

The network becomes visually organized and stable.

**Camera:**

Slow pull back to reveal the entire network.

**On-Screen Text:**

> LEARN PATTERNS

---

## Scene 05 — Takeaway

**Time:** 0:24–0:28

**VO:**

> “That's the basic idea behind neural network learning.”

**VO Direction:**

Confident and concise.

**Animation:**

Simplify the screen.

Show the complete loop:

> GUESS → ERROR → ADJUST → LEARN

Each word appears sequentially.

**Camera:**

Hold steady.

---

## Scene 06 — Next Episode

**Time:** 0:28–0:30

**VO:**

> “Next: what is the neuron actually doing?”

**VO Direction:**

Curious, slightly faster, designed to create anticipation.

**Animation:**

Zoom into one neuron.

The surrounding network fades into the background.

The selected neuron remains visible.

**On-Screen Text:**

> NEXT: THE ARTIFICIAL NEURON

End on the neuron.

# 24. Production Quality Checklist

Before approving a 30-second Short:

## Story

- [ ] The Short has one central idea.
- [ ] The hook is understandable immediately.
- [ ] The explanation has a logical progression.
- [ ] The ending reinforces the main idea.
- [ ] No unnecessary concepts were added.

## Voice

- [ ] VO fits within approximately 30 seconds.
- [ ] Delivery instructions are included.
- [ ] Important terms have emphasis guidance.
- [ ] Pauses match visual transitions.
- [ ] The narration sounds natural.

## Animation

- [ ] Every major VO statement has a corresponding visual.
- [ ] Animation explains rather than distracts.
- [ ] Camera movement has a purpose.
- [ ] Important visual changes happen at the correct narration moment.
- [ ] No unnecessary motion dominates the scene.

## Text

- [ ] Text is concise.
- [ ] Text is readable on a phone.
- [ ] Critical text follows the safe-zone standard.
- [ ] Text does not duplicate every spoken sentence.
- [ ] No scene contains excessive text.

## Safe Zone

- [ ] Right-side UI area is protected.
- [ ] Bottom UI area is protected.
- [ ] Important content has edge margin.
- [ ] Camera movement preserves safe placement.
- [ ] Final frames remain safe.

## Series Continuity

- [ ] Visual language matches previous episodes.
- [ ] Terminology is consistent.
- [ ] The episode connects naturally to the series.
- [ ] The next episode can be teased without distracting from the current lesson.

---

# 25. Core Production Principle

The most important rule for this series is:

> **The voice explains the idea. The animation makes the idea visible. The text reinforces the idea. The camera directs attention to the idea.**

If the viewer hears an explanation but cannot see what is happening, the animation needs improvement.

If the viewer can understand the animation without the narration, the scene is usually strong.

If both work together, the Short becomes easier to understand, remember, and share.

---

# 26. Final 30-Second Rule

> **One Short = one core idea.**
>
> Hook quickly.
>
> Explain visually.
>
> Synchronize VO and animation.
>
> Remove unnecessary information.
>
> Keep critical content inside the Shorts safe zone.
>
> End with one memorable takeaway.
